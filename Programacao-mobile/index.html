Aula 2 · Fundamentos

Prepare o ambiente

O Expo reúne ferramentas que tornam o desenvolvimento React Native mais rápido, desde a criação até a execução do aplicativo.

Instalação passo a passo

  1. Instale a versão LTS do Node.js em nodejs.org.
  2. Confirme no terminal com node --version e npm --version.
  3. Instale o VS Code e as extensões recomendadas pelo professor.
  4. Abra o terminal na pasta em que o app será criado.
  5. Crie o projeto com o template Blank do Expo.
  6. Entre na pasta do projeto e inicie com npx expo start.

Comandos essenciais

# criar um projeto Expo
npx create-expo-app meuApp

# entrar no projeto
cd meuApp

# iniciar o servidor
npx expo start

# executar no navegador
# pressione W no terminal do Expo
Erro no modo web?
Interrompa com Ctrl+C e execute npx expo install react-dom react-native-web. Depois rode o Expo novamente.

Aula 2 · Linguagem

TypeScript sem medo

TypeScript é um superset do JavaScript: código JavaScript válido também funciona nele, mas com tipagem estática e verificação antes da execução.

Por que tipar?

O tipo esperado de uma variável, parâmetro ou retorno fica explícito. O editor oferece autocomplete melhor e muitos erros aparecem antes de o app rodar.

// JavaScript: concatena e resulta em "53"
function soma(a, b) { return a + b; }
soma(5, "3");

// TypeScript: o erro aparece no editor
function soma(a: number, b: number): number {
  return a + b;
}
soma(5, "3");

Tipos básicos

let nome: string = "Maria";
let idade: number = 25;
let ativo: boolean = true;

let notas: number[] = [8, 9.5, 7];
let nomes: Array<string> = ["Ana", "Bia"];

// any aceita tudo, mas deve ser evitado
let dado: any = "texto";

number cobre inteiros e decimais. O tipo any desliga a verificação e remove o principal benefício da linguagem.

Funções, interfaces e types

function apresentar(nome: string, idade: number): string {
  return `${nome} tem ${idade} anos.`;
}

interface Usuario {
  nome: string;
  idade: number;
  email?: string; // opcional
}

type Status = "ativo" | "inativo";
let usuario: Usuario = { nome: "Ana", idade: 25 };
function mostrar(usuario: Usuario) {
  console.log(`${usuario.nome} tem ${usuario.idade} anos.`);
}

Interfaces descrevem a estrutura de objetos e são muito usadas para tipar props. type também descreve objetos, mas é mais flexível e pode representar uniões, como Status.

Aula 3 · Reutilização

Componentes e props

Um componente filho recebe informações do componente pai por meio de props, como uma função recebe parâmetros.

Crie uma pasta de componentes

Na raiz, crie src/Components/Title.tsx. Um único componente pode ser usado várias vezes com valores diferentes.

import { Text } from "react-native";

interface TitleProps {
  texto: string;
  tamanho?: number;
}

export function Title({ texto, tamanho = 24 }: TitleProps) {
  return <Text style={{ fontSize: tamanho }}>{texto}</Text>;
}

O pai passa os valores

import { View } from "react-native";
import { Title } from "./src/Components/Title";

export default function App() {
  return (
    <View>
      <Title texto="Programação Mobile" />
      <Title texto="React Native" tamanho={30} />
      <Title texto="TypeScript" tamanho={20} />
    </View>
  );
}

O pai usa o filho; o filho recebe as props e só se preocupa em renderizar com os dados recebidos.

Props também podem carregar ações

interface BotaoProps {
  texto: string;
  aoClicar: () => void;
}

function Botao({ texto, aoClicar }: BotaoProps) {
  return (
    <Button title={texto} onPress={aoClicar} />
  );
}

<Botao texto="Salvar" aoClicar={() => console.log("salvou")} />

Uma função passada por prop permite que o filho avise o pai quando algo acontece. No navegador, observe a mensagem pelo console do DevTools (F12). O Alert do React Native é voltado ao ambiente nativo.

Aula 4 · Estado e efeitos

Hooks que dão vida à tela

Hooks permitem estado e efeitos em componentes funcionais, além de favorecer o reuso de lógica por meio de hooks customizados.

useState: memória local

useState(valorInicial) devolve um par: o valor atual e a função que o atualiza. Ao chamar o setter, o componente renderiza novamente.

import { useState } from "react";

export default function Contador() {
  const [contador, setContador] = useState(0);

  return (
    <View>
      <Text>Você clicou {contador} vezes</Text>
      <Button
        title="Incrementar"
        onPress={() => setContador(prev => prev + 1)}
      />
      <Button title="Zerar" onPress={() => setContador(0)} />
    </View>
  );
}

Prefira prev => prev + 1 quando o novo valor depende do anterior: assim a atualização usa sempre o estado mais recente.

Estado pode controlar a interface

const [darkMode, setDarkMode] = useState(false);

<View style={{
  flex: 1,
  backgroundColor: darkMode ? "#000" : "#fff",
  alignItems: "center",
  justifyContent: "center"
}}>
  <Text style={{ color: darkMode ? "#fff" : "#000" }}>
    Modo escuro: {darkMode ? "Ativado" : "Desativado"}
  </Text>
  <Switch value={darkMode} onValueChange={setDarkMode} />
</View>

O operador ternário escolhe o conteúdo ou estilo conforme o estado: condição verdadeira ? resultado verdadeiro : resultado falso.

useEffect: efeitos colaterais

Use-o para dizer ao React: “depois de renderizar, execute esta ação”. Exemplos: buscar dados, assinar eventos, iniciar timer ou sincronizar com armazenamento.

import { useEffect } from "react";

useEffect(() => {
  console.log("executa quando o componente monta");

  return () => {
    console.log("cleanup antes de desmontar");
  };
}, []);

A função de cleanup é opcional e libera recursos antes da próxima execução ou quando o componente desmonta.

Os três modos do useEffect

// toda renderização
useEffect(() => { ... });

// uma vez, ao montar
useEffect(() => { ... }, []);

// quando userId mudar
useEffect(() => {
  buscarDados(userId);
}, [userId]);

Regras de ouro dos Hooks

  • Chame hooks sempre no topo do componente.
  • Não chame useState ou useEffect dentro de if, for ou funções comuns.
  • A ordem de chamadas precisa ser a mesma em todas as renderizações.
  • Hooks só devem ser chamados em componentes funcionais React ou em hooks customizados.
Por que isso importa?
Quebrar a ordem pode causar o erro “Rendered fewer hooks than expected”.
Revisão

Consulta rápida

Clique nos cartões para revelar a resposta e abra as perguntas para conferir seu raciocínio.

1. Qual a diferença entre pai e filho?

O pai utiliza o componente e envia props; o filho recebe essas props e renderiza sua parte da interface.

2. Por que evitar o tipo any?

Porque ele aceita qualquer valor e desliga a verificação estática, anulando a segurança que o TypeScript oferece.

3. Quando usar cleanup no useEffect?

Quando o efeito cria algo que precisa ser liberado, como listener, timer, conexão ou inscrição.

4. Qual a diferença entre useState e useEffect?

useState guarda e altera dados que afetam a tela; useEffect executa efeitos colaterais depois da renderização.
