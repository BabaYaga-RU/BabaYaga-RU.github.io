Aula 2 · Começo

Configure e execute

O objetivo é criar um projeto Expo, iniciar o servidor e abrir a mesma aplicação no navegador, no celular ou em um emulador.

1. Prepare as ferramentas

  1. Instale o Node.js LTS pelo site oficial. O npm vem junto e instala dependências.
  2. Instale o VS Code e abra a pasta onde seus projetos ficarão.
  3. No VS Code, abra o terminal em Terminal → New Terminal.
  4. Confirme o ambiente com os comandos do cartão ao lado.
Por que LTS?
É a versão com suporte mais estável para acompanhar o curso e reduzir incompatibilidades.

2. Verifique o terminal

node --version
npm --version

Os dois comandos devem imprimir versões. Se node ou npm não for reconhecido, feche e reabra o VS Code depois da instalação; se persistir, corrija o PATH do Node.

O que é o npm?

É o gerenciador que baixa bibliotecas e executa scripts do projeto. O npx executa uma ferramenta de um pacote sem exigir instalação global.

3. Crie o primeiro projeto

# entre na pasta de projetos
cd caminho/para/seus-projetos

# crie um app Expo
npx create-expo-app@latest meuApp

# entre na pasta criada
cd meuApp

# inicie o servidor de desenvolvimento
npx expo start

O comando cria a pasta meuApp com código, dependências e configuração. Quando o Expo mostrar o menu no terminal, pressione W para abrir a versão web. Para usar um celular, escaneie o QR Code pelo Expo Go na mesma rede.

Template: as telas do assistente podem oferecer Default ou Blank. Para acompanhar os exemplos simples deste guia, escolha um template que gere App.tsx como tela inicial.

4. Se a web não abrir

  1. Interrompa o processo com Ctrl+C.
  2. Instale os pacotes web na versão compatível com o projeto.
  3. Inicie o Expo novamente e pressione W.
npx expo install react-dom react-native-web
npx expo start

Use expo install, e não um npm install com versões escolhidas no acaso: o Expo seleciona versões compatíveis.

Como o ciclo funciona

  1. Você edita App.tsx.
  2. O Metro bundler transforma e reúne os módulos.
  3. O Expo envia a atualização para web, celular ou emulador.
  4. O React Native renderiza componentes nativos ou equivalentes web.

Salvar o arquivo dispara Fast Refresh. Se o estado puder ser preservado, a tela atualiza sem reiniciar tudo.

Aula 2 · Linguagem

TypeScript com propósito

TypeScript adiciona verificação de tipos ao JavaScript. Ele é convertido para JavaScript antes de rodar; a tipagem ajuda enquanto você escreve.

Tipos básicos

let nome: string = "Maria";
let idade: number = 25;
let ativo: boolean = true;

let notas: number[] = [8, 9.5, 7];
let nomes: Array<string> = [
  "Ana",
  "Bia"
];

number cobre inteiros e decimais. Prefira tipos específicos; any aceita tudo e desliga a proteção justamente naquele trecho.

Função: entrada e saída

function apresentar(
  nome: string,
  idade: number
): string {
  return `${nome} tem ${idade} anos.`;
}

const frase = apresentar("Ana", 25);

Os tipos depois dos parâmetros descrevem entradas. O tipo depois de ) descreve o retorno. O editor avisa se você passar um tipo incompatível.

Interface, type e propriedade opcional

interface Usuario {
  nome: string;
  idade: number;
  email?: string;
}

type Status = "ativo" | "inativo";

const usuario: Usuario = {
  nome: "Ana",
  idade: 25
};

function mostrar(usuario: Usuario): void {
  console.log(usuario.nome);
}

Uma interface descreve a forma de um objeto. type também pode fazer isso e ainda representa uniões, como Status. O ? torna email opcional. Esse mesmo recurso será usado para tipar props.

Como ler um erro de tipo

Se uma função pede number e você passa uma string, corrija a origem ou converta conscientemente. Não use any para esconder o aviso: isso transforma um erro visível em um erro de execução.

function soma(a: number, b: number) {
  return a + b;
}

soma(5, 3); // certo
// soma(5, "3"); // erro

Regra prática

  • Tipar props e retornos de componentes.
  • Usar união quando há opções fechadas.
  • Usar unknown quando o valor é desconhecido e validar antes de usar.
  • Evitar any em código novo.
Aula 3 · Reutilização

Pai, filho e props

O pai usa o componente filho e envia dados por props. O filho recebe esses dados e renderiza sua parte da interface.

1. Crie o componente filho

Na raiz do projeto, crie src/Components/Title.tsx. O componente abaixo recebe um texto obrigatório e um tamanho opcional.

import { Text } from "react-native";

interface TitleProps {
  texto: string;
  tamanho?: number;
}

export function Title({
  texto,
  tamanho = 24
}: TitleProps) {
  return (
    <Text style={{ fontSize: tamanho }}>
      {texto}
    </Text>
  );
}

2. Use no componente pai

import { View } from "react-native";
import { Title } from "./src/Components/Title";

export default function App() {
  return (
    <View>
      <Title texto="Programação Mobile" />
      <Title
        texto="React Native"
        tamanho={30}
      />
    </View>
  );
}

O mesmo componente é usado duas vezes com valores diferentes. Isso evita duplicar estrutura e concentra a regra visual no filho.

3. Props podem transportar eventos

import { Button } from "react-native";

interface BotaoProps {
  texto: string;
  aoClicar: () => void;
}

export function Botao({
  texto,
  aoClicar
}: BotaoProps) {
  return (
    <Button
      title={texto}
      onPress={aoClicar}
    />
  );
}

<Botao
  texto="Salvar"
  aoClicar={() => console.log("salvou")}
/>

aoClicar é uma função sem argumentos que não retorna valor. No navegador, veja a mensagem em DevTools com F12 → Console. Alert deve ser testado no ambiente nativo; ele não se comporta como uma caixa web comum.

Props não são estado

Props vêm do pai e devem ser tratadas como somente leitura. Se o componente precisa mudar um valor por causa de uma interação, use estado no componente adequado.

Checklist do componente

  • Nome começa com letra maiúscula.
  • Arquivo exporta o componente.
  • Props têm interface.
  • Importação aponta para o caminho correto.
  • O componente retorna um elemento nativo ou fragmento.
Aula 4 · Estado e efeitos

Hooks passo a passo

useState guarda informação que muda a tela. useEffect sincroniza o componente com algo externo depois da renderização.

useState: memória da tela

import { useState } from "react";
import { Button, Text, View } from "react-native";

export default function Contador() {
  const [contador, setContador] = useState(0);

  function incrementar() {
    setContador(valorAtual => valorAtual + 1);
  }

  return (
    <View>
      <Text>Cliques: {contador}</Text>
      <Button
        title="Incrementar"
        onPress={incrementar}
      />
    </View>
  );
}

O setter agenda uma nova renderização. Use a forma valorAtual => novoValor quando o próximo valor depende do anterior.

Estado controla a interface

const [escuro, setEscuro] = useState(false);

<Switch
  value={escuro}
  onValueChange={setEscuro}
/>

<Text>
  Modo: {escuro ? "escuro" : "claro"}
</Text>

O componente renderiza de novo com o novo estado. Não altere diretamente uma variável comum esperando que a tela se atualize.

useEffect: quando e por que usar

Efeitos são ações fora do cálculo puro da interface: buscar dados, iniciar timer, assinar evento ou sincronizar armazenamento. O callback roda depois da renderização.

import { useEffect } from "react";

useEffect(() => {
  console.log("componente montou");

  return () => {
    console.log("componente desmontou");
  };
}, []);

A função retornada é o cleanup. Ela remove listener, cancela timer ou encerra inscrição antes de o efeito ser refeito ou quando o componente desmonta.

Os três modos

// toda renderização
useEffect(() => {
  console.log("renderizou");
});

// uma vez ao montar
useEffect(() => {
  carregarDados();
}, []);

// quando userId mudar
useEffect(() => {
  buscarDados(userId);
}, [userId]);

Exemplo com timer

useEffect(() => {
  const id = setInterval(() => {
    console.log("tic");
  }, 1000);

  return () => clearInterval(id);
}, []);

Sem clearInterval, cada montagem pode deixar um timer ativo. Cleanup evita vazamentos e efeitos duplicados.

Regras dos Hooks

  • Chame hooks no topo do componente, sempre na mesma ordem.
  • Não coloque useState ou useEffect dentro de if, for ou função comum.
  • Inclua nas dependências os valores externos usados pelo efeito.
  • Não use efeito para calcular algo que pode ser calculado durante a renderização.
  • Se o efeito atualiza um estado que está nas dependências sem condição, investigue loop infinito.
Prática guiada

Monte uma tela completa

Este exercício combina ambiente, componente, props, estado e efeito em uma sequência que você consegue executar no projeto criado.

Objetivo

Crie uma tela que recebe um título por prop, conta cliques com useState e registra no console quando o componente monta e desmonta.

Passo 1: arquivo do componente

import { useEffect, useState } from "react";
import { Button, Text, View } from "react-native";

interface PainelProps {
  titulo: string;
}

export function Painel({ titulo }: PainelProps) {
  const [cliques, setCliques] = useState(0);

  useEffect(() => {
    console.log("Painel montado");

    return () => console.log("Painel removido");
  }, []);

  return (
    <View>
      <Text>{titulo}</Text>
      <Text>Cliques: {cliques}</Text>
      <Button
        title="Somar"
        onPress={() => setCliques(valor => valor + 1)}
      />
    </View>
  );
}

Passo 2: use no App.tsx

import { View } from "react-native";
import { Painel } from "./src/Components/Painel";

export default function App() {
  return (
    <View>
      <Painel titulo="Minha atividade" />
      <Painel titulo="Outra atividade" />
    </View>
  );
}

Como testar

  1. Salve os arquivos e abra com npx expo start.
  2. Pressione W ou abra no Expo Go.
  3. Clique em cada botão e confirme o contador independente.
  4. Abra o Console e procure “Painel montado”.
  5. Altere o App para remover um painel e observe o cleanup.

O que você aprendeu

  • PainelProps valida os dados que entram.
  • O pai renderiza o filho e escolhe o título.
  • Cada instância possui seu próprio estado.
  • O efeito roda na montagem e o cleanup na remoção.
Revisão

Confira seu raciocínio

Tente responder antes de abrir cada explicação.

Por que usar Expo no começo?

Ele fornece ferramentas e um fluxo pronto para iniciar, testar e distribuir um app React Native sem configurar toda a cadeia nativa manualmente.

Qual a diferença entre props e state?

Props são dados recebidos do pai e tratados como somente leitura. State é memória interna alterada pelo setter, provocando nova renderização.

Por que uma função pode ser passada como prop?

Para o filho comunicar uma ação ao pai. O pai decide o que acontece e o filho apenas chama a função ao detectar o evento.

Quando o array vazio do useEffect é adequado?

Quando a ação deve ocorrer uma vez na montagem, como carregar dados inicial ou configurar um recurso, sempre limpando o recurso quando necessário.

O que causa um loop de useEffect?

Um efeito que altera uma dependência a cada execução, ou uma dependência instável criada durante a renderização. Revise a lógica e as dependências.
