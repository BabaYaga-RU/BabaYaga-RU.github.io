Aula 1 – Introdução à Teoria de Grafos

Um grafo G = (V, E) é uma estrutura matemática composta por um conjunto de vértices (V) e um conjunto de arestas (E) que conectam pares de vértices.

  • Vértice (nó): entidade do problema (cidade, pessoa, processo)
  • Aresta: relacionamento entre dois vértices (estrada, amizade, dependência)
  • Grau de um vértice: número de arestas incidentes nele
Aplicações reais: redes de computadores, rotas de GPS (menor caminho), redes sociais (análise de influência), compiladores (grafo de dependências), bioinformática (redes proteicas).

1.1 Problema das Pontes de Königsberg (1736)

Euler resolveu o problema histórico: "É possível percorrer todas as 7 pontes de Königsberg exatamente uma vez e voltar ao ponto de partida?"

Euler provou que não, modelando as margens como vértices e as pontes como arestas. Sua conclusão: uma trilha euleriana (que passa por todas as arestas exatamente uma vez) exige 0 ou 2 vértices de grau ímpar; para voltar ao ponto inicial, formando um circuito euleriano, todos os graus devem ser pares.

Este problema deu origem à Teoria de Grafos. O grafo resultante tinha 4 vértices e 7 arestas, com todos os vértices de grau ímpar (3 ou 5), impossibilitando o circuito.

Em um dígrafo, distingue-se grau de entrada e grau de saída. Um vértice u é antecessor de v quando existe arco u → v; v é sucessor de u.

Alcançabilidade e fechos transitivos

  • Fecho transitivo direto de v: vértices alcançáveis partindo de v.
  • Fecho transitivo inverso de v: vértices a partir dos quais é possível alcançar v.
  • O próprio vértice pertence aos dois fechos por ser alcançável a partir dele mesmo.

Aula 2 – Representação Computacional de Grafos

2.1 Matriz de Adjacência

Uma matriz n×n onde A[i][j] = 1 (ou peso) se existe aresta entre i e j, 0 caso contrário.

// Java – Grafo com Matriz de Adjacência
class GrafoMatriz {
    int[][] adj;
    int n;
    
    GrafoMatriz(int n) {
        this.n = n;
        adj = new int[n][n];
    }
    
    void addAresta(int u, int v) {    // grafo não-dirigido
        adj[u][v] = 1;
        adj[v][u] = 1;
    }
    
    void addArestaPeso(int u, int v, int w) {
        adj[u][v] = w;
        adj[v][u] = w;
    }
    
    boolean existeAresta(int u, int v) {
        return adj[u][v] != 0;
    }
    
    void imprimir() {
        for (int[] linha : adj) {
            for (int val : linha) System.out.printf("%3d", val);
            System.out.println();
        }
    }
}

EspaçoO(V²) — ruim para grafos esparsos
Verificar arestaO(1)
Listar vizinhosO(V)
Ideal paraGrafos densos (muitas arestas)

2.2 Lista de Adjacência

Cada vértice possui uma lista de seus vizinhos. Mais eficiente para grafos esparsos.

import java.util.*;

class GrafoLista {
    int n;
    List<List<Integer>> adj;
    
    GrafoLista(int n) {
        this.n = n;
        adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    }
    
    void addAresta(int u, int v) {
        adj.get(u).add(v);
        adj.get(v).add(u);   // remover para dígrafo
    }
    
    List<Integer> vizinhos(int u) {
        return adj.get(u);
    }
}

// Versão com pesos (aresta como objeto)
class Aresta {
    int destino, peso;
    Aresta(int d, int p) { destino = d; peso = p; }
}

2.3 Conteúdo incorporado dos slides: conjecturas, contraexemplos e indução

Testar vários casos pode sugerir uma conjectura, mas não prova que ela vale sempre. Um único contraexemplo basta para derrubá-la, como ocorreu com a conjectura de Fermat sobre números da forma 22ⁿ + 1.

Estrutura de uma prova por indução

  1. Passo base: provar que P(n₀) é verdadeira.
  2. Hipótese indutiva: assumir P(k) verdadeira para um k arbitrário.
  3. Passo indutivo: usando a hipótese, provar P(k + 1).

Indução aparece em provas sobre complexidade, corretude de algoritmos, grafos e árvores. Exemplos clássicos são:

  • 1 + 2 + ... + n = n(n + 1)/2;
  • a soma dos n primeiros ímpares é n²;
  • o número de vértices de grau ímpar é sempre par;
  • Kn possui n(n − 1)/2 arestas.
Como provar a última fórmula: cada um dos n vértices pode ligar-se a n − 1 outros, produzindo n(n − 1) incidências. Cada aresta foi contada duas vezes, então divide-se por 2.

Aula 3 – Algoritmos de Percurso

3.1 BFS – Busca em Largura (Breadth-First Search)

Visita os vértices camada por camada, explorando todos os vizinhos antes de ir mais fundo. Usa uma fila.

void bfs(GrafoLista g, int inicio) {
    boolean[] visitado = new boolean[g.n];
    Queue<Integer> fila = new LinkedList<>();
    
    visitado[inicio] = true;
    fila.offer(inicio);
    
    while (!fila.isEmpty()) {
        int v = fila.poll();
        System.out.print(v + " ");
        
        for (int vizinho : g.vizinhos(v)) {
            if (!visitado[vizinho]) {
                visitado[vizinho] = true;
                fila.offer(vizinho);
            }
        }
    }
}
Usos do BFS: menor caminho em grafos não-ponderados, verificar se grafo é bipartido, nível de separação em redes sociais, algoritmos de roteamento em redes.
ComplexidadeValor
TempoO(V + E)
EspaçoO(V) — tamanho da fila

3.2 DFS – Busca em Profundidade (Depth-First Search)

Explora o mais fundo possível antes de voltar. Pode ser implementada com pilha ou recursão.

// DFS recursiva
void dfs(GrafoLista g, int v, boolean[] visitado) {
    visitado[v] = true;
    System.out.print(v + " ");
    
    for (int vizinho : g.vizinhos(v)) {
        if (!visitado[vizinho]) {
            dfs(g, vizinho, visitado);
        }
    }
}

// Chamada
boolean[] vis = new boolean[g.n];
dfs(g, 0, vis);  // inicia no vértice 0

// DFS iterativa com pilha
void dfsIterativa(GrafoLista g, int inicio) {
    boolean[] visitado = new boolean[g.n];
    Stack<Integer> pilha = new Stack<>();
    pilha.push(inicio);
    
    while (!pilha.isEmpty()) {
        int v = pilha.pop();
        if (visitado[v]) continue;
        visitado[v] = true;
        System.out.print(v + " ");
        for (int viz : g.vizinhos(v))
            if (!visitado[viz]) pilha.push(viz);
    }
}
Usos do DFS: detecção de ciclos, ordenação topológica, componentes fortemente conexos (algoritmo de Tarjan/Kosaraju), labirintos, resolução de puzzles.

3.3 Conteúdo incorporado dos slides: isomorfismo, subgrafos e caminhamentos

Isomorfismo

Dois grafos são isomorfos quando existe uma bijeção entre seus vértices que preserva adjacências. Eles podem ter desenhos diferentes e ainda representar a mesma estrutura.

Antes de procurar a bijeção, compare invariantes: número de vértices e arestas, sequência de graus, quantidade de componentes, ciclos e vértices de cada grau. Se algum deles difere, os grafos não são isomorfos; igualdade desses valores, sozinha, não garante isomorfismo.

Subgrafos e disjunção

H = (V′, E′) é subgrafo de G = (V, E) quando V′ ⊆ V, E′ ⊆ E e cada aresta mantém as mesmas extremidades. Dois subgrafos podem ser aresta-disjuntos sem serem vértice-disjuntos.

Passeio, trajeto, caminho e circuito

ObjetoRegra principal
PasseioPode repetir vértices e arestas
Trajeto / trilhaNão repete arestas, mas pode repetir vértices
CaminhoNão repete vértices
Circuito / cicloCaminhamento fechado sem repetição indevida

Em grafo não ponderado, o comprimento é o número de arestas; em grafo ponderado, normalmente é a soma dos pesos.

Aula 4 – Caminhos Mínimos e Ciclos

4.1 Algoritmo de Dijkstra

Encontra o menor caminho de um vértice fonte a todos os outros em grafos com pesos não-negativos.

import java.util.*;

void dijkstra(int[][] grafo, int src, int n) {
    int[] dist = new int[n];
    boolean[] visitado = new boolean[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // PriorityQueue: {distancia, vertice}
    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
    pq.offer(new int[]{0, src});
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (visitado[u]) continue;
        visitado[u] = true;
        
        for (int v = 0; v < n; v++) {
            if (grafo[u][v] != 0 && dist[u] + grafo[u][v] < dist[v]) {
                dist[v] = dist[u] + grafo[u][v];
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    // dist[] contém as menores distâncias de src a cada vértice
}
ComplexidadeCom arrayCom fila de prioridade
TempoO(V²)O((V+E) log V)*
EspaçoO(V)O(V+E)
* Atenção à representação: O((V+E) log V) exige fila de prioridade combinada com lista de adjacência. A implementação acima usa matriz e percorre todos os V possíveis vizinhos, mantendo O(V²) como custo dominante.
Limitação: Dijkstra não funciona com pesos negativos. Para isso, use o algoritmo de Bellman-Ford O(VE).

4.3 Conteúdo incorporado dos slides: maximal, máximo e conectividade

Máximo não é maximal

  • Maximal: não pode ser ampliado sem perder a propriedade desejada.
  • Máximo: possui o maior tamanho possível entre todas as soluções.

Toda solução máxima é maximal, mas uma solução maximal pode ser menor que a máxima. Essa diferença aparece em conjuntos independentes, emparelhamentos e subgrafos com determinada propriedade.

Componentes e limites de arestas

Cada componente é um subgrafo conexo maximal. Um grafo é desconexo se, e somente se, seus vértices podem ser particionados em dois conjuntos não vazios sem aresta entre eles.

Para um grafo simples com n vértices e k componentes:

n − k ≤ m ≤ (n − k)(n − k + 1)/2

O limite inferior ocorre quando cada componente é uma árvore. O superior ocorre concentrando o máximo de vértices possível em uma componente completa e deixando as demais isoladas.

Ponte: em um grafo conexo, remover uma aresta desconecta o grafo exatamente quando essa aresta não pertence a nenhum ciclo.

Aula 5 – Árvores Geradoras Mínimas

Uma Árvore Geradora Mínima (AGM / MST) de um grafo conexo ponderado é uma subárvore que conecta todos os vértices com o menor custo total de arestas possível.

Aplicações: redes de telecomunicações, distribuição elétrica, projeto de circuitos.

5.1 Algoritmo de Kruskal

Estratégia gulosa: ordena arestas por peso crescente e adiciona cada aresta se não forma ciclo (Union-Find).

class KruskalMST {
    int[] pai, rank;
    
    int find(int x) {
        if (pai[x] != x) pai[x] = find(pai[x]);  // path compression
        return pai[x];
    }
    
    void union(int x, int y) {
        int px = find(x), py = find(y);
        if (rank[px] < rank[py]) pai[px] = py;
        else if (rank[px] > rank[py]) pai[py] = px;
        else { pai[py] = px; rank[px]++; }
    }
    
    int[][] kruskal(int n, int[][] arestas) {
        // arestas[i] = {peso, u, v}
        Arrays.sort(arestas, (a,b) -> a[0]-b[0]);
        pai = new int[n]; rank = new int[n];
        for (int i = 0; i < n; i++) pai[i] = i;
        
        List<int[]> mst = new ArrayList<>();
        for (int[] e : arestas) {
            if (find(e[1]) != find(e[2])) {
                union(e[1], e[2]);
                mst.add(e);
                if (mst.size() == n-1) break;
            }
        }
        return mst.toArray(new int[0][]);
    }
}

Complexidade: O(E log E) para ordenar + O(E α(V)) para Union-Find ≈ O(E log E)

5.2 Algoritmo de Prim

Cresce a árvore a partir de um vértice inicial, sempre adicionando a aresta de menor peso que conecta um novo vértice.

void prim(int[][] grafo, int n) {
    int[] chave = new int[n];      // peso mínimo para entrar na MST
    boolean[] inMST = new boolean[n];
    int[] pai = new int[n];
    
    Arrays.fill(chave, Integer.MAX_VALUE);
    chave[0] = 0; pai[0] = -1;
    
    for (int i = 0; i < n-1; i++) {
        // encontra vértice com menor chave não incluído
        int u = -1;
        for (int v = 0; v < n; v++)
            if (!inMST[v] && (u == -1 || chave[v] < chave[u])) u = v;
        inMST[u] = true;
        
        for (int v = 0; v < n; v++) {
            if (grafo[u][v] != 0 && !inMST[v] && grafo[u][v] < chave[v]) {
                chave[v] = grafo[u][v];
                pai[v] = u;
            }
        }
    }
}

Complexidade: O(V²) com array simples; O(E log V) com fila de prioridade

OperaçãoResultado

Aula 6 – Aplicações e Coloração de Grafos

Coloração de Grafos

Atribuir cores a vértices de forma que nenhum par de vértices adjacentes tenha a mesma cor, usando o mínimo de cores possível (número cromático χ(G)).

  • Grafos bipartidos: χ = 2 (se não vazio)
  • Grafos com ciclo ímpar: χ ≥ 3
  • Grafo completo Kn: χ = n
Teorema das 4 Cores: qualquer mapa planar pode ser colorido com no máximo 4 cores. Provado em 1976 com auxílio computacional (Appel e Haken).

Aplicação: Alocação de Registradores

Compiladores modelam a interferência entre variáveis como um grafo de interferência e usam coloração para alocar registradores de CPU — cada cor representa um registrador físico.

Fluxo em Redes (Ford-Fulkerson)

Em um dígrafo com capacidades nas arestas, o fluxo máximo da fonte ao sumidouro é determinado pelo corte mínimo (Teorema Max-Flow Min-Cut).

// Algoritmo de Ford-Fulkerson (BFS = Edmonds-Karp, O(VE²))
int fordFulkerson(int[][] cap, int s, int t, int n) {
    int[][] residual = new int[n][n];
    for (int u = 0; u < n; u++)
        for (int v = 0; v < n; v++) residual[u][v] = cap[u][v];
    
    int maxFlow = 0;
    int[] pai = new int[n];
    
    while (bfsAumentante(residual, s, t, n, pai)) {
        int fluxoCaminho = Integer.MAX_VALUE;
        for (int v = t; v != s; v = pai[v])
            fluxoCaminho = Math.min(fluxoCaminho, residual[pai[v]][v]);
        for (int v = t; v != s; v = pai[v]) {
            residual[pai[v]][v] -= fluxoCaminho;
            residual[v][pai[v]] += fluxoCaminho;
        }
        maxFlow += fluxoCaminho;
    }
    return maxFlow;
}

Ordenação Topológica

Para DAGs (grafos dirigidos acíclicos): ordenar vértices de forma que toda aresta u→v tenha u antes de v na ordenação. Usado em: make/build systems, resolução de dependências, planejamento de tarefas.

// Usando DFS
void topoSort(GrafoLista g, int v, boolean[] vis, Stack<Integer> pilha) {
    vis[v] = true;
    for (int u : g.vizinhos(v))
        if (!vis[u]) topoSort(g, u, vis, pilha);
    pilha.push(v);  // adiciona após explorar todos os descendentes
}

// Resultado: pop da pilha dá a ordenação topológica

6.4 Conteúdo incorporado dos slides: propriedades de árvores

Caracterizações equivalentes

Para um grafo G com n vértices, as afirmações abaixo caracterizam uma árvore:

  • G é conexo e não possui ciclos;
  • G é conexo e possui n − 1 arestas;
  • G não possui ciclos e possui n − 1 arestas;
  • existe exatamente um caminho entre cada par de vértices;
  • adicionar uma aresta entre dois vértices cria exatamente um ciclo.
Remover qualquer aresta de uma árvore a desconecta; adicionar qualquer aresta cria um ciclo.

Árvores enraizadas e binárias

  • Uma árvore com raiz distinguida é enraizada; sem raiz, é livre.
  • O nível de um vértice é sua distância até a raiz.
  • A altura é o maior nível, isto é, o maior caminho partindo da raiz.
  • Em uma árvore binária completa no sentido dos slides, todo vértice interno possui dois filhos.

Se uma árvore binária cheia possui i vértices internos e p folhas, então p = i + 1 e o total é n = 2p − 1, portanto n é ímpar. Com altura h, o número de folhas satisfaz p ≤ 2h.

Aplicação: um torneio eliminatório com p participantes exige p − 1 jogos, pois cada jogo elimina exatamente um participante.

7. Preparação para a Prova — Conceitos, Deduções e Algoritmos

COMO ESTUDAR ESTA SEÇÃO

O simulado verifica definições diretas: grafo conexo, completo, bipartido, caminho, ciclo, componente, grau e matriz de adjacência. Uma prova mais exigente tende a fornecer um grafo, uma sequência de graus ou uma matriz e pedir que você deduza propriedades, escolha um algoritmo e justifique a resposta.

Em cada questão, identifique primeiro: o grafo é dirigido? possui pesos? é simples? é conexo? O problema trata de vértices, arestas, caminhos ou custo? Essas respostas eliminam boa parte das alternativas erradas.

O simulado cobra

  • Definições de caminho, ciclo e componente
  • Conectividade, completude e bipartição
  • Soma dos graus e vértices ímpares
  • Dimensão da matriz de adjacência

A prova pode elevar para

  • Aplicar fórmulas e deduzir arestas/graus
  • Ler matriz e reconstruir propriedades
  • Escolher BFS, DFS, Dijkstra, Prim ou Kruskal
  • Distinguir Euler, Hamilton, menor caminho e AGM

Uma componente conexa não é apenas qualquer subgrafo conexo: é um subgrafo conexo maximal, isto é, não pode receber outro vértice do grafo mantendo a conectividade.

Dirigidos: em dígrafos, “fortemente conexo” significa que existe caminho dirigido de u para v e de v para u para todo par. “Fracamente conexo” ignora as direções para testar conectividade.

7.2 Grau, número de arestas e fórmulas essenciais

Lema do aperto de mãos: Σ grau(v) = 2|E|

Cada aresta não dirigida toca dois vértices, portanto contribui duas unidades à soma dos graus. Duas consequências importantes:

  • A soma dos graus sempre é par.
  • A quantidade de vértices com grau ímpar sempre é par.

7.4 Conectividade, componentes e bipartição

BFS e DFS podem marcar todos os vértices alcançáveis a partir de uma origem. Para contar componentes em um grafo não dirigido, execute uma nova busca sempre que encontrar um vértice ainda não visitado.

componentes = 0
para cada vértice v:
    se v não foi visitado:
        BFS_ou_DFS(v)
        componentes++

Para verificar se um grafo é bipartido, use BFS ou DFS atribuindo duas cores. Todo vizinho deve receber a cor oposta. Se uma aresta ligar vértices da mesma cor, o grafo não é bipartido.

Um grafo não dirigido é bipartido se, e somente se, não possui ciclo de comprimento ímpar.
Aplicação: modelar relações entre dois tipos distintos de entidade, como alunos e disciplinas, candidatos e vagas, máquinas e tarefas.

Não confunda: Dijkstra encontra menores caminhos partindo de uma origem. Prim e Kruskal encontram uma árvore de custo total mínimo. Uma árvore geradora mínima não garante o menor caminho entre cada par de vértices.

Se um grafo conexo possui n vértices e n − 1 arestas, ele é árvore. Se uma árvore ganhar uma nova aresta, surge exatamente um ciclo. Se perder uma aresta, fica desconexa.

7.7 Exercícios resolvidos — nível prova

1. Um grafo não dirigido possui graus 3, 3, 2, 2, 2 e 2. Quantas arestas possui?
Resposta: a soma dos graus é 14. Pelo lema do aperto de mãos, 2|E| = 14, então |E| = 7. Há dois vértices ímpares, quantidade que confirma a regra de paridade.
2. Quantas arestas faltam para um grafo simples com 6 vértices e 11 arestas tornar-se completo?
Resposta: K6 possui 6×5/2 = 15 arestas. Faltam 15 − 11 = 4 arestas.
3. Um grafo possui um ciclo de comprimento 5. Ele pode ser bipartido?
Resposta: não. Um ciclo de comprimento ímpar impede a coloração consistente com apenas duas cores, portanto o grafo não é bipartido.
4. Um grafo não dirigido possui 8 vértices distribuídos em 3 componentes. Qual o número mínimo de arestas a adicionar para torná-lo conexo?
Resposta: 2. Cada nova aresta pode unir duas componentes; para unir c componentes são necessárias no mínimo c − 1 arestas.
5. Por que BFS encontra menor caminho em grafo não ponderado, mas DFS não garante?
Resposta: BFS visita por camadas de distância: primeiro todos a uma aresta, depois a duas e assim por diante. A primeira vez que alcança um vértice usa o menor número de arestas. DFS pode seguir profundamente por uma rota longa antes de encontrar uma rota curta.
6. Um grafo ponderado tem uma aresta de peso negativo. Qual problema existe ao usar Dijkstra?
Resposta: Dijkstra considera definitiva a menor distância de um vértice quando o remove da fila de prioridade. Uma aresta negativa descoberta depois pode reduzir essa distância, invalidando a decisão. Para pesos negativos, considere Bellman-Ford.
Checklist de armadilhas:
  • Componente conexa é maximal; qualquer caminho isolado dentro dela não é outra componente.
  • Grafo completo conecta todo par; grafo conexo exige apenas algum caminho entre os pares.
  • Bipartido não significa “ter dois vértices”; significa dividir os vértices em duas partes sem arestas internas.
  • Caminho mínimo, árvore geradora mínima e percurso de Euler resolvem problemas diferentes.
  • Em dígrafos, grau de entrada e grau de saída devem ser analisados separadamente.

Clique em um card para conferir a resposta. Fechado, ele mostra apenas o tópico; aberto, cresce conforme o conteúdo.

FundamentoO que define um grafo G = (V, E)?
Resposta

Um conjunto de vértices V, que representam entidades, e um conjunto de arestas E, que representam relações entre pares de vértices.

FórmulaQual é a relação entre graus e arestas?
Resposta

Em um grafo não direcionado, a soma dos graus de todos os vértices é igual a 2|E|. Cada aresta contribui com duas incidências.

FórmulaQuantas arestas possui o grafo completo Kn?
Resposta

Kn possui n(n − 1)/2 arestas, pois todo par de vértices distintos está conectado.

ConceitoQual é a diferença entre passeio, trilha e caminho?
Resposta

Um passeio pode repetir vértices e arestas. Uma trilha não repete arestas. Um caminho não repete vértices.

EulerQuando existe trilha ou circuito euleriano?
Resposta

Em um grafo conexo, existe circuito euleriano quando todos os vértices têm grau par. Existe trilha euleriana aberta quando exatamente dois vértices têm grau ímpar.

ComparaçãoEuler e Hamilton tratam do quê?
Resposta

Euler busca percorrer cada aresta exatamente uma vez. Hamilton busca visitar cada vértice exatamente uma vez.

BipartiçãoComo reconhecer um grafo bipartido?
Resposta

Seus vértices podem ser divididos em dois conjuntos sem arestas dentro do mesmo conjunto. Equivalentemente, o grafo não possui ciclo de comprimento ímpar.

RepresentaçãoQuando usar matriz de adjacência?
Resposta

É adequada para grafos densos ou quando verificar rapidamente a existência de uma aresta é prioridade. Usa espaço O(V²).

RepresentaçãoQuando usar lista de adjacência?
Resposta

É adequada para grafos esparsos e para percorrer os vizinhos de um vértice. Usa espaço O(V + E).

AlgoritmoQuando a BFS encontra o menor caminho?
Resposta

Em grafos não ponderados, ou quando todas as arestas têm o mesmo custo. Ela explora os vértices por níveis usando uma fila.

AlgoritmoPara que a DFS é especialmente útil?
Resposta

Para explorar profundamente um ramo, detectar ciclos, identificar componentes e apoiar ordenação topológica. Normalmente usa pilha ou recursão.

Menor caminhoQual é a limitação principal do Dijkstra?
Resposta

Dijkstra não deve ser usado quando há arestas com peso negativo, pois sua escolha gulosa pode consolidar uma distância incorreta.

Árvore geradoraComo funciona o algoritmo de Kruskal?
Resposta

Ordena as arestas por peso e adiciona as menores que não formam ciclo, normalmente usando Union-Find, até obter V − 1 arestas.

Árvore geradoraComo funciona o algoritmo de Prim?
Resposta

Parte de um vértice e expande uma única árvore escolhendo sempre a aresta de menor peso que conecta a árvore a um novo vértice.

ÁrvoreQuais propriedades caracterizam uma árvore?
Resposta

É um grafo conexo e sem ciclos. Com n vértices, possui n − 1 arestas e existe exatamente um caminho simples entre cada par de vértices.

DAGQuando existe ordenação topológica?
Resposta

Somente em grafos dirigidos acíclicos. A ordenação coloca cada vértice antes de todos os vértices que dependem dele.

PlanaridadeQual é a fórmula de Euler para grafos planares?
Resposta

Para um grafo planar conexo, V − E + F = 2, considerando também a face externa.

EstruturaO que significa dois grafos serem isomorfos?
Resposta

Eles possuem a mesma estrutura de adjacências, embora os nomes e o desenho dos vértices possam ser diferentes.

ConectividadeO que é uma componente conexa?
Resposta

É um subgrafo conexo maximal: dentro dele há caminho entre quaisquer dois vértices, e não é possível adicionar outro vértice mantendo essa propriedade.

ColoraçãoO que é o número cromático?
Resposta

É a menor quantidade de cores necessária para colorir os vértices de modo que vértices adjacentes tenham cores diferentes.
