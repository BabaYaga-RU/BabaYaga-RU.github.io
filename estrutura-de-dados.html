Aula 1 – Introdução às Estruturas de Dados

Uma estrutura de dados é uma forma organizada de armazenar e gerenciar dados na memória para que possam ser usados de maneira eficiente. A escolha da estrutura certa impacta diretamente no desempenho do algoritmo.

  • Estruturas lineares: vetores, listas, pilhas, filas
  • Estruturas não-lineares: árvores, grafos, tabelas hash
  • Complexidade de tempo: notação Big-O mede o crescimento do tempo em função do tamanho n da entrada

1.1 JVM e Gerenciamento de Memória (Java)

A Java Virtual Machine (JVM) divide a memória em áreas distintas:

ÁreaO que armazena
Stack (Pilha de chamadas)Variáveis locais, parâmetros, referências de objetos, frames de métodos
HeapObjetos criados com new, arrays; gerenciado pelo Garbage Collector
MetaspaceMetadados de classes, métodos, campos (substituiu PermGen no Java 8+)
Registradores de PCEndereço da instrução atual por thread
Native Method StackChamadas a métodos nativos (C/C++)
Stack vs Heap: Variáveis primitivas (int, double) ficam na stack; objetos (String, arrays, instâncias de classe) ficam no Heap. A stack é LIFO e de acesso rápido. O Heap é maior mas mais lento (GC overhead).

1.3 Conteúdo incorporado dos slides: aplicações, vetores, ordenação e busca

Por que precisamos de estruturas de dados?

Os tipos primitivos não bastam para representar todos os problemas. Estruturas de dados organizam valores primitivos em tipos construídos, permitindo armazenar, localizar e transformar informações com eficiência.

  • Persistência temporária: manter na RAM dados recuperados de bancos, arquivos ou rede evita acessos externos repetidos e mais lentos.
  • Processamento de imagens: uma imagem é discretizada em uma matriz de pixels; no padrão RGB, cada pixel combina componentes vermelha, verde e azul.
  • Escolha da estrutura: depende das operações mais frequentes, do crescimento esperado e da forma de acesso aos dados.

Vetores em Java

Um vetor é uma estrutura homogênea unidimensional, alocada sequencialmente e acessada por índices iniciados em zero. Como qualquer variável, possui nome, tipo, endereço de memória, valor, escopo e tempo de vida.

int[] valores = new int[4];       // aloca quatro inteiros, iniciados com 0
double[] notas = {1.5, 3.6, 7.77};

valores[0] = 10;
System.out.println(valores[0]);
Atenção: para um vetor de tamanho n, os índices válidos vão de 0 a n - 1. Acessar outra posição causa ArrayIndexOutOfBoundsException.

Ordenação simples e busca binária

TécnicaPré-condiçãoIdeiaCusto
Busca sequencialNenhumaExaminar elemento por elementoO(n)
Bubble sortNenhumaComparar vizinhos e trocar os fora de ordemO(n²)
Busca bináriaVetor ordenadoDescartar metade do intervalo a cada comparaçãoO(log n)
int buscaBinaria(int[] v, int alvo) {
    int inicio = 0, fim = v.length - 1;
    while (inicio <= fim) {
        int meio = inicio + (fim - inicio) / 2;
        if (v[meio] == alvo) return meio;
        if (v[meio] < alvo) inicio = meio + 1;
        else fim = meio - 1;
    }
    return -1;
}
Raciocínio esperado: ordenar antes de uma única busca pode custar mais que uma busca sequencial. A busca binária compensa quando o vetor já está ordenado ou será consultado muitas vezes.

Aula 2 – Vetores e Listas Ligadas

2.1 Vetores (Arrays)

Um vetor é uma coleção de elementos do mesmo tipo armazenados em posições de memória contíguas. O acesso é O(1) pelo índice.

// Java – array estático
int[] numeros = new int[5];
numeros[0] = 10;
numeros[4] = 50;

// Java – ArrayList (array dinâmico)
import java.util.ArrayList;
ArrayList<Integer> lista = new ArrayList<>();
lista.add(10);
lista.add(20);
lista.remove(0);      // remove por índice
System.out.println(lista.get(0)); // 20
OperaçãoArray estáticoArrayList
Acesso por índiceO(1)O(1)
Inserção no final (havendo espaço)O(1)O(1) amortizado
Inserção no meioO(n)O(n)
Remoção no meioO(n)O(n)
Busca linearO(n)O(n)
Quando usar vetor: Quando você precisa de acesso aleatório rápido e o tamanho é relativamente fixo. Prefira ArrayList em Java para flexibilidade.

2.2 Listas Ligadas (Linked Lists)

Uma lista ligada é composta por nós, cada um contendo um valor e um ponteiro para o próximo nó. Não requer memória contígua.

// Java – implementação de nó
class No {
    int valor;
    No proximo;
    No(int v) { valor = v; proximo = null; }
}

class ListaLigada {
    No cabeca;
    
    void inserirInicio(int v) {
        No novo = new No(v);
        novo.proximo = cabeca;
        cabeca = novo;
    }
    
    void inserirFim(int v) {
        No novo = new No(v);
        if (cabeca == null) { cabeca = novo; return; }
        No atual = cabeca;
        while (atual.proximo != null) atual = atual.proximo;
        atual.proximo = novo;
    }
    
    void imprimir() {
        No atual = cabeca;
        while (atual != null) {
            System.out.print(atual.valor + " -> ");
            atual = atual.proximo;
        }
        System.out.println("null");
    }
}
OperaçãoLista SimplesLista Dupla
Acesso por índiceO(n)O(n)
Inserção no inícioO(1)O(1)
Inserção no fimO(n) / O(1)*O(1)
Remoção por valorO(n)O(n)
* O(1) se mantiver ponteiro para o fim
Cuidado: Listas ligadas têm overhead de memória (armazenam ponteiro além do valor) e cache-miss mais frequente que arrays (memória não contígua).

2.3 Conteúdo incorporado dos slides: matrizes, memória, JVM e ponteiros

Matrizes e armazenamento

Matrizes são estruturas homogêneas com mais de uma dimensão. Cada dimensão exige um índice; em matriz[linha][coluna], percorrer todas as posições de uma matriz m × n custa O(m · n).

int[][] matriz = new int[3][4];
for (int linha = 0; linha < matriz.length; linha++) {
    for (int coluna = 0; coluna < matriz[linha].length; coluna++) {
        matriz[linha][coluna] = linha + coluna;
    }
}

Uma imagem em tons de cinza pode ser vista como uma matriz de intensidades; uma imagem RGB pode ser modelada por três matrizes, uma para cada canal de cor.

Formas de alocação de memória

FormaCaracterísticaExemplo
EstáticaTamanho definido previamente e sem crescimento durante a execuçãoArray de tamanho fixo
LinearLiberação segue uma ordem, como uma pilha de chamadasVariáveis locais e chamadas de métodos
DinâmicaObjetos são criados conforme a necessidadeObjetos no heap e nodos de uma lista

Na JVM, o código Java é compilado para bytecode. Durante a execução, o interpretador e o compilador JIT transformam trechos em código nativo. Objetos ficam, em geral, no heap; chamadas e referências locais são controladas pela pilha. O coletor de lixo recupera objetos que deixaram de ser alcançáveis.

Referências Java versus ponteiros C

Os slides apresentam ponteiros para explicar listas e memória. Em C, um ponteiro armazena um endereço: &x obtém o endereço de x e *p acessa o valor apontado. O ponteiro deve ser inicializado antes do uso, e sua aritmética avança conforme o tamanho do tipo.

Ponteiro em CReferência em Java
Permite desreferenciação e aritmética explícitasAcesso ao objeto é controlado pela linguagem
Pode apontar para regiões inválidasNão expõe endereços nem aritmética de ponteiros
Gerenciamento manual pode causar vazamentosObjetos não alcançáveis podem ser coletados pela JVM
Pegadinha: copiar uma referência Java não copia o objeto. Duas variáveis podem referenciar o mesmo objeto e observar as mesmas alterações.

Aula 3 – Pilhas e Filas

3.1 Pilhas (Stack) – LIFO

Uma pilha segue o princípio Last In, First Out: o último elemento inserido é o primeiro a ser removido. Analogia: pilha de pratos.

import java.util.Stack;

Stack<Integer> pilha = new Stack<>();
pilha.push(10);   // empilha
pilha.push(20);
pilha.push(30);

System.out.println(pilha.peek());  // 30 (topo, sem remover)
System.out.println(pilha.pop());   // 30 (remove)
System.out.println(pilha.isEmpty()); // false
System.out.println(pilha.size());    // 2

Implementação com Array:

class Pilha {
    int[] dados;
    int topo = -1;
    Pilha(int capacidade) { dados = new int[capacidade]; }
    
    void push(int v) {
        if (topo == dados.length - 1) throw new RuntimeException("Pilha cheia!");
        dados[++topo] = v;
    }
    int pop() {
        if (topo == -1) throw new RuntimeException("Pilha vazia!");
        return dados[topo--];
    }
    int peek() { return dados[topo]; }
    boolean isEmpty() { return topo == -1; }
}
Usos práticos de pilhas: histórico de navegação (voltar/avançar), undo/redo em editores, avaliação de expressões matemáticas (notação polonesa reversa), chamadas de funções recursivas na JVM, parsing de HTML/XML.
Java moderno: para implementar pilha, normalmente prefira a interface Deque com ArrayDeque. A classe legada Stack continua útil para compreender as operações cobradas na disciplina.

3.2 Filas (Queue) – FIFO

Uma fila segue o princípio First In, First Out: o primeiro elemento inserido é o primeiro a ser removido. Analogia: fila de banco.

import java.util.LinkedList;
import java.util.Queue;

Queue<String> fila = new LinkedList<>();
fila.offer("Alice");   // enfileira (preferível a add)
fila.offer("Bob");
fila.offer("Carlos");

System.out.println(fila.peek());   // "Alice" (frente, sem remover)
System.out.println(fila.poll());   // "Alice" (remove)
System.out.println(fila.size());   // 2

Fila Circular com Array:

class FilaCircular {
    int[] dados;
    int inicio = 0, fim = 0, tamanho = 0;
    FilaCircular(int cap) { dados = new int[cap]; }
    
    void enqueue(int v) {
        if (tamanho == dados.length) throw new RuntimeException("Fila cheia!");
        dados[fim] = v;
        fim = (fim + 1) % dados.length;
        tamanho++;
    }
    int dequeue() {
        if (tamanho == 0) throw new RuntimeException("Fila vazia!");
        int v = dados[inicio];
        inicio = (inicio + 1) % dados.length;
        tamanho--;
        return v;
    }
}
Usos práticos de filas: sistemas de impressão, escalonamento de processos no SO, BFS (busca em largura em grafos), buffers de comunicação, processamento de tarefas em background.

3.3 Conteúdo incorporado dos slides: estruturas dinâmicas e listas encadeadas

Vetores são simples, compactos e permitem acesso direto, mas têm tamanho fixo e podem exigir deslocamentos em inserções e remoções. Estruturas dinâmicas relacionam nodos alocados durante a execução, crescendo ou diminuindo conforme necessário.

AspectoVetorLista encadeada
Posição na memóriaContíguaNodos podem estar separados
Acesso ao elemento iO(1)O(n)
Inserção no inícioO(n), por deslocamentosO(1)
Memória adicionalBaixaReferência para o próximo nodo
class Nodo {
    float valor;
    Nodo proximo;
}

Uma lista simplesmente encadeada precisa conhecer o primeiro nodo. Manter também uma referência para o último torna a inserção no final O(1). As operações essenciais são inserir, remover, verificar se está vazia, consultar início/fim e percorrer os nodos.

Invariante central: todo nodo, exceto o último, aponta para seu sucessor; o último aponta para null. Uma atualização de referência na ordem errada pode desconectar parte da lista.

Aula 4 – Árvores

Uma árvore é uma estrutura hierárquica não-linear composta por nós conectados por arestas, sem ciclos.

  • Raiz: nó sem pai (único)
  • Folha: nó sem filhos
  • Altura: maior profundidade da raiz até uma folha
  • Grau: número de filhos de um nó

4.1 Árvore Binária de Busca (BST)

Propriedade fundamental: para cada nó, todos os valores na subárvore esquerda são menores, e na direita são maiores.

class No {
    int valor;
    No esq, dir;
    No(int v) { valor = v; }
}

class BST {
    No raiz;
    
    No inserir(No no, int v) {
        if (no == null) return new No(v);
        if (v < no.valor) no.esq = inserir(no.esq, v);
        else if (v > no.valor) no.dir = inserir(no.dir, v);
        return no;
    }
    
    // Em-ordem: visita esq → raiz → dir (resultado ordenado!)
    void emOrdem(No no) {
        if (no == null) return;
        emOrdem(no.esq);
        System.out.print(no.valor + " ");
        emOrdem(no.dir);
    }
    
    boolean buscar(No no, int v) {
        if (no == null) return false;
        if (v == no.valor) return true;
        return v < no.valor ? buscar(no.esq, v) : buscar(no.dir, v);
    }
}
OperaçãoBST (médio)BST (pior)
BuscaO(log n)O(n) — árvore degenerada
InserçãoO(log n)O(n)
RemoçãoO(log n)O(n)

4.2 Árvore AVL (Auto-balanceada)

A Árvore AVL mantém o balanceamento automático: a diferença de altura entre subárvores esq e dir de qualquer nó é no máximo 1 (fator de balanceamento ∈ {-1, 0, 1}).

class NoAVL {
    int valor, altura;
    NoAVL esq, dir;
    NoAVL(int v) { valor = v; altura = 1; }
}

// Fator de balanceamento
int fb(NoAVL n) {
    if (n == null) return 0;
    return altura(n.esq) - altura(n.dir);
}

// Rotação simples à direita
NoAVL rotDir(NoAVL y) {
    NoAVL x = y.esq;
    NoAVL T2 = x.dir;
    x.dir = y;
    y.esq = T2;
    y.altura = Math.max(altura(y.esq), altura(y.dir)) + 1;
    x.altura = Math.max(altura(x.esq), altura(x.dir)) + 1;
    return x;
}
Rotações AVL: Quando o fator de balanceamento sai de [-1,1], aplica-se uma das 4 rotações: rotação direita (LL), rotação esquerda (RR), rotação dupla esquerda-direita (LR), rotação dupla direita-esquerda (RL).
OperaçãoAVL (garantido)
BuscaO(log n)
InserçãoO(log n)
RemoçãoO(log n)

4.3 Conteúdo incorporado dos slides: implementações e operações em listas

Lista linear por arranjo ou por referências

Uma lista linear pode ser implementada sobre um arranjo ou por nodos encadeados. O arranjo economiza referências e permite acesso O(1), mas limita o tamanho e torna inserções/remoções internas O(n). A implementação encadeada cresce dinamicamente, mas exige percurso para localizar posições.

Operação encadeadaAtualizações indispensáveis
Inserir no inícioNovo aponta para o antigo primeiro; primeiro passa a ser o novo
Inserir no finalÚltimo aponta para o novo; último passa a ser o novo
Inserir após um nodoNovo recebe o antigo sucessor; nodo anterior aponta para o novo
Remover primeiroPrimeiro passa a apontar para o segundo
Remover últimoLocalizar antecessor; torná-lo último e apontar para null
Remover específicoAntecessor passa a apontar para o sucessor do removido
Casos-limite sempre cobrados: lista vazia, lista com um único nodo, remoção do primeiro/último e atualização simultânea de primeiro e ultimo.

Lista ordenada

Para manter uma lista ordenada, procure o primeiro nodo maior ou igual ao valor inserido e conecte o novo nodo entre o antecessor e esse nodo. A busca da posição custa O(n), mesmo que a alteração dos ponteiros custe O(1).

5.1 Complexidade: raciocinar em vez de decorar

Big-O descreve como o custo cresce quando a entrada aumenta. Para resolver questões de prova, identifique a operação que mais cresce e descarte constantes e termos menores.

PadrãoRaciocínioComplexidade
Acesso direto v[i]O endereço é calculado sem percorrer elementosO(1)
Um laço de 0 até nExecuta aproximadamente n vezesO(n)
Dois laços independentes até nn × n operaçõesO(n²)
Índice dividido por 2 a cada passoQuantidade de divisões até chegar a 1O(log n)
Operações sequenciais O(n) + O(n²)O termo dominante venceO(n²)
// O(n²), mesmo que o laço interno execute quantidades diferentes:
for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)
        operacao();
0 + 1 + 2 + ... + (n − 1) = n(n − 1)/2 → O(n²)
Custo amortizado: adicionar ao final de um ArrayList costuma ser O(1), mas ocasionalmente exige copiar todo o array em O(n). Distribuído entre muitas inserções, o custo médio por inserção continua O(1) amortizado.

5.3 Arrays, matrizes e listas em nível de implementação

Arrays e matrizes

O acesso por índice é constante porque a posição pode ser calculada diretamente. Em uma representação bidimensional contígua por linhas, a posição lógica de matriz[i][j] é:

deslocamento = i × quantidadeDeColunas + j

Inserir no meio de um array exige deslocar os elementos posteriores. Remover também exige fechar o espaço deixado. Por isso, ambas são O(n).

Detalhe de Java: int[][] é um array de referências para outros arrays. As linhas podem até ter tamanhos diferentes; portanto, é uma matriz lógica, não necessariamente um único bloco contíguo.

Listas ligadas e atualização de ponteiros

Ao remover um nó atual de uma lista simples, o nó anterior deve passar a apontar para o sucessor:

anterior.proximo = atual.proximo

Em lista dupla, a ligação precisa permanecer consistente nos dois sentidos:

anterior.proximo = proximo    e    proximo.anterior = anterior
  • Trate separadamente lista vazia, remoção da cabeça e remoção da cauda.
  • Não perca a referência do restante da lista ao trocar ponteiros.
  • Lista dupla gasta mais memória, mas permite navegação reversa e remoção mais conveniente quando o nó é conhecido.

5.4 Pilhas, filas e invariantes

Um invariante é uma condição que deve continuar verdadeira antes e depois de cada operação.

EstruturaInvariante importanteFalha típica
Pilha em arraytopo == -1 significa vazia; topo aponta para o último válidoUnderflow ao fazer pop vazia; overflow ao exceder capacidade
Fila circularInício aponta para o próximo a sair; fim para a próxima posição livreConfundir fila cheia com vazia
Fila encadeadaAo remover o último elemento, início e fim devem ficar nulosManter ponteiro de fim inválido
próxima posição circular = (posiçãoAtual + 1) % capacidade

Rastreio rápido: após push(4), push(7), pop(), push(9), a pilha contém [4, 9] e peek() devolve 9.

5.5 Árvores: o conteúdo que diferencia a prova

Em uma BST, todos os valores da subárvore esquerda são menores que a raiz e todos os da direita são maiores, conforme a regra adotada para duplicatas.

PercursoOrdemUso típico
Pré-ordemraiz → esquerda → direitaCopiar/serializar estrutura
Em-ordemesquerda → raiz → direitaProduzir valores ordenados em uma BST
Pós-ordemesquerda → direita → raizRemover/liberar uma árvore
Por nívelcamada por camada com filaMenor profundidade e visualização

Remover um nó de BST exige analisar três casos: folha; nó com um filho; nó com dois filhos. No terceiro caso, substitui-se normalmente pelo sucessor em-ordem (menor valor da subárvore direita) ou predecessor.

fator de balanceamento AVL = altura(esquerda) − altura(direita)
Reconhecimento de rotação: inserções 30, 20, 10 formam caso LL e pedem rotação simples à direita. Inserções 30, 10, 20 formam caso LR e pedem rotação dupla esquerda-direita.

5.6 Exercícios resolvidos — nível prova

1. Um algoritmo percorre uma lista para encontrar um valor e, ao encontrá-lo, remove o nó. Qual é a complexidade total?
Resposta: O(n). A remoção pode ser O(1) quando o nó e seu anterior já são conhecidos, mas localizar o valor exige percorrer até n nós. Custos sequenciais O(n) + O(1) resultam em O(n).
2. Por que acesso por índice é O(1) em array e O(n) em lista encadeada?
Resposta: o array permite calcular diretamente o endereço lógico da posição. A lista possui apenas referências entre nós; para chegar à posição i, é necessário seguir os ponteiros desde a cabeça.
3. Uma fila circular de capacidade 5 possui fim = 4. Onde será feita a próxima inserção após avançar o fim?
Resposta: na posição 0, pois (4 + 1) % 5 = 0. O módulo faz o índice retornar ao início sem deslocar os elementos.
4. Insira 50, 30, 70, 20, 40, 60 e 80 em uma BST. Qual é o percurso em-ordem?
Resposta: 20, 30, 40, 50, 60, 70, 80. O percurso em-ordem de uma BST visita os valores em ordem crescente.
5. Uma BST pode ter busca O(n)? Explique.
Resposta: sim. Se os valores forem inseridos em ordem crescente, a BST pode degenerar em uma lista, com altura n. Uma AVL realiza rotações para limitar a altura e garantir O(log n).
6. Qual estrutura escolher para implementar “desfazer/refazer” e por quê?
Resposta: duas pilhas. “Desfazer” retira a ação mais recente da pilha de executadas e a coloca na pilha de desfeitas; “refazer” realiza o movimento contrário. O comportamento é naturalmente LIFO.
Checklist de armadilhas:
  • O(1) não significa “instantâneo”; significa que o custo não cresce com n.
  • Lista dupla navega nos dois sentidos, mas ainda não oferece acesso direto por índice.
  • Pilha usa LIFO; fila comum usa FIFO; fila de prioridade não preserva necessariamente chegada.
  • Uma BST só tem O(log n) médio quando sua altura permanece controlada.
  • Não confunda custo da operação com custo de encontrar o local onde ela será feita.
