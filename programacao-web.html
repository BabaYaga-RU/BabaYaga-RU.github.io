1. Formulários HTML

Formulários HTML são o principal mecanismo para coleta de dados do usuário na web. A tag <form> define o container do formulário com atributos que controlam como e para onde os dados são enviados.

Atributos essenciais de <form>:

AtributoValoresDescrição
actionURLDestino para onde os dados serão enviados. Ex: action="resposta.php"
methodGET | POSTMétodo HTTP. GET: dados na URL (visíveis). POST: dados no corpo da requisição (mais seguro para senhas).
enctypemultipart/form-dataNecessário para upload de arquivos.
novalidate(booleano)Desabilita a validação nativa do browser.

Estrutura básica de um formulário:

<form action="resposta.php" method="POST">

  <fieldset>
    <legend>Dados Pessoais</legend>

    <label for="nome">Nome:</label>
    <input type="text" id="nome" name="nome" required
           placeholder="Digite seu nome completo"
           minlength="3" maxlength="100">

    <label for="email">E-mail:</label>
    <input type="email" id="email" name="email" required>

    <button type="submit">Enviar</button>
    <button type="reset">Limpar</button>
  </fieldset>

</form>

Tags especiais de agrupamento:

  • <fieldset> — agrupa visualmente campos relacionados com uma borda. Melhora a organização e acessibilidade.
  • <legend> — título descritivo do fieldset. Aparece na borda superior do grupo.
  • <label> — rótulo do campo. Ao clicar no label, o foco vai para o campo associado via atributo for (deve ser igual ao id do input).

3. Tabelas HTML

Tabelas organizam dados em linhas e colunas. Devem ser usadas apenas para dados tabulares, não para layout de página.

Tags de uma tabela:

TagDescrição
<table>Container principal da tabela.
<thead>Cabeçalho semântico (opcional, mas bom para acessibilidade).
<tbody>Corpo da tabela com os dados.
<tfoot>Rodapé semântico (totais, notas).
<tr>Table Row — uma linha da tabela.
<th>Table Header — célula de cabeçalho (negrito por padrão). Atributo scope.
<td>Table Data — célula de dado.
<caption>Título descritivo da tabela (acessibilidade).

Atributos de mesclagem de células:

  • colspan="N" — célula ocupa N colunas. Ex: cabeçalho que engloba várias colunas.
  • rowspan="N" — célula ocupa N linhas. Ex: célula de categoria que agrupa várias linhas.

4. Introdução ao React

React é uma biblioteca JavaScript criada pelo Facebook para construir interfaces de usuário componentizadas e reativas. "Reativa" significa que a interface se atualiza automaticamente quando o estado muda.

Por que React?

  • Componentização: divida a interface em peças reutilizáveis com lógica própria.
  • Virtual DOM: o React calcula as mudanças necessárias eficientemente antes de atualizar o DOM real.
  • Ecossistema: enorme comunidade, bibliotecas, ferramentas (Vite, Next.js, etc.).
  • One-way data flow: dados fluem do pai para o filho via props, facilitando o rastreamento de estado.

Criando um projeto React com Vite:

# Criar novo projeto
npm create vite@latest meu-projeto -- --template react
cd meu-projeto
npm install
npm run dev

Estrutura do projeto criado pelo Vite:

meu-projeto/
  index.html          ← entrada do browser
  package.json        ← dependências e scripts
  vite.config.js      ← configuração do Vite
  public/             ← arquivos estáticos
  src/
    main.jsx          ← ponto de entrada React
    App.jsx           ← componente raiz
    App.css           ← estilos do App

main.jsx — ponto de entrada:

import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
)

5. JSX

JSX (JavaScript XML) é uma extensão de sintaxe para JavaScript que parece HTML mas é transformada em chamadas de funções JavaScript. É o "dialeto" do React para descrever a interface.

Regras do JSX:

  • Toda tag deve ser fechada: <br />, <img />, <input />
  • Retorno de componente deve ter um único elemento raiz. Use <div> ou fragmento <>...</>.
  • Atributos são camelCase: className (não class), htmlFor (não for), onClick.
  • Expressões JavaScript dentro do JSX ficam entre chaves {}.
  • Comentários: {/* comentário */}
// Exemplos de JSX
const nome = "Maria";
const idade = 20;

function App() {
  return (
    <>
      <h1>Olá, {nome}!</h1>
      <p>Você tem {idade} anos e em 10 anos terá {idade + 10}.</p>
      <p className="destaque">Texto em destaque</p>
      {/* Isso é um comentário em JSX */}
      <img src="/foto.jpg" alt="Foto do usuário" />
    </>
  );
}
className em vez de class porque class é palavra reservada no JavaScript.

6. Componentes e Props

Um componente é uma função JavaScript que retorna JSX. É a unidade fundamental de construção de interfaces em React.

6.1 Criando um Componente

// Componente funcional (forma moderna)
function Saudacao() {
  return <h1>Olá, Mundo!</h1>;
}

// Componente com múltiplas linhas de JSX
function CartaoAluno() {
  return (
    <div className="cartao">
      <h2>Perfil do Aluno</h2>
      <p>Nome: João Silva</p>
      <p>Curso: Engenharia de Software</p>
    </div>
  );
}

6.2 Props (Propriedades)

Props são parâmetros passados para o componente pelo componente pai. Funcionam como argumentos de função — permitem que o mesmo componente exiba dados diferentes.

// Componente recebe props como objeto
function CartaoAluno(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>Matrícula: {props.matricula}</p>
      <p>Nota: {props.nota}</p>
    </div>
  );
}

// Usando destructuring (mais limpo e recomendado)
function CartaoAluno({ nome, matricula, nota }) {
  return (
    <div className="cartao">
      <h2>{nome}</h2>
      <p>Matrícula: {matricula}</p>
      <p>Nota: {nota}</p>
    </div>
  );
}

// App.jsx — usando o componente com props
function App() {
  return (
    <div>
      <CartaoAluno nome="Ana Silva" matricula="2024001" nota={9.5} />
      <CartaoAluno nome="João Souza" matricula="2024002" nota={7.0} />
      <CartaoAluno nome="Maria Lima" matricula="2024003" nota={8.5} />
    </div>
  );
}
Props são somente leitura! Um componente nunca deve modificar suas próprias props. Para dados que mudam, use o hook useState.

7. Hook useState

O useState é o hook mais fundamental do React. Permite que componentes funcionais tenham e gerenciem estado — dados que podem mudar e quando mudam causam a re-renderização do componente.

Sintaxe:

import { useState } from 'react';

// Declaração
const [valorEstado, setValorEstado] = useState(valorInicial);

// Onde:
// valorEstado     = valor atual do estado (somente leitura direto)
// setValorEstado  = função para atualizar o estado
// valorInicial    = valor inicial (executado apenas uma vez)

Regras dos Hooks:

  • Só podem ser chamados no topo do componente — nunca dentro de if, for, ou funções aninhadas.
  • Só podem ser usados em componentes funcionais ou hooks customizados.

Exemplo simples — Contador:

import { useState } from 'react';

function Contador() {
  const [contagem, setContagem] = useState(0);  // começa com 0

  function incrementar() {
    setContagem(contagem + 1);   // atualiza → re-renderiza
  }

  function decrementar() {
    setContagem(contagem - 1);
  }

  function zerar() {
    setContagem(0);
  }

  return (
    <div>
      <h2>Contagem: {contagem}</h2>
      <button onClick={incrementar}>+1</button>
      <button onClick={decrementar}>-1</button>
      <button onClick={zerar}>Zerar</button>
    </div>
  );
}

Estado com strings e inputs controlados:

function FormNome() {
  const [nome, setNome] = useState('');

  return (
    <div>
      <input
        type="text"
        value={nome}                          // valor controlado pelo estado
        onChange={(e) => setNome(e.target.value)}  // atualiza a cada tecla
        placeholder="Digite seu nome"
      />
      <p>Olá, {nome || '...'}</p>
    </div>
  );
}
Input controlado: o valor do input é sempre determinado pelo estado React (value={nome}), não pelo DOM. Isso garante que o React tenha controle total sobre o formulário.

8. Projeto: Calculadora

A calculadora exemplifica o uso de múltiplos estados em um componente e como cada input controlado tem seu próprio estado.

import { useState } from 'react';
import './App.css';

function App() {
  const [num1, setNum1] = useState('');      // primeiro número (string do input)
  const [num2, setNum2] = useState('');      // segundo número
  const [resultado, setResultado] = useState(''); // resultado calculado

  function calcular(operacao) {
    const a = parseFloat(num1);
    const b = parseFloat(num2);

    if (isNaN(a) || isNaN(b)) {
      setResultado('Erro: insira números válidos');
      return;
    }

    let res;
    switch (operacao) {
      case '+': res = a + b; break;
      case '-': res = a - b; break;
      case '*': res = a * b; break;
      case '/':
        if (b === 0) { setResultado('Erro: divisão por zero'); return; }
        res = a / b;
        break;
      default: return;
    }
    setResultado(res);
  }

  return (
    <div className="calculadora">
      <h1>Calculadora</h1>
      <input
        type="number"
        value={num1}
        onChange={(e) => setNum1(e.target.value)}
        placeholder="Número 1"
      />
      <input
        type="number"
        value={num2}
        onChange={(e) => setNum2(e.target.value)}
        placeholder="Número 2"
      />
      <div className="botoes">
        <button onClick={() => calcular('+')}>+</button>
        <button onClick={() => calcular('-')}>-</button>
        <button onClick={() => calcular('*')}>×</button>
        <button onClick={() => calcular('/')}>÷</button>
      </div>
      {resultado !== '' && (
        <p className="resultado">Resultado: <strong>{resultado}</strong></p>
      )}
    </div>
  );
}

export default App;

9. Projeto: Todo List

O projeto Todo List introduz o uso de array no estado, adição de itens com spread operator e remoção com filter.

import { useState } from 'react';

function App() {
  const [tarefas, setTarefas] = useState([]);   // array de tarefas
  const [novaTarefa, setNovaTarefa] = useState('');  // texto digitado

  function adicionarTarefa() {
    const texto = novaTarefa.trim();
    if (!texto) return;  // não adiciona tarefa vazia

    // spread operator: cria novo array com todas as tarefas + a nova
    setTarefas([...tarefas, { id: Date.now(), texto }]);
    setNovaTarefa('');   // limpa o campo
  }

  function removerTarefa(id) {
    // filter: cria novo array sem o elemento com o id especificado
    setTarefas(tarefas.filter((t) => t.id !== id));
  }

  function handleKeyDown(e) {
    if (e.key === 'Enter') adicionarTarefa();  // adicionar ao pressionar Enter
  }

  return (
    <div className="todo">
      <h1>Lista de Tarefas ({tarefas.length})</h1>

      <div className="adicionar">
        <input
          type="text"
          value={novaTarefa}
          onChange={(e) => setNovaTarefa(e.target.value)}
          onKeyDown={handleKeyDown}
          placeholder="Nova tarefa..."
        />
        <button onClick={adicionarTarefa}>Adicionar</button>
      </div>

      <ul>
        {tarefas.map((tarefa) => (
          <li key={tarefa.id}>
            {tarefa.texto}
            <button onClick={() => removerTarefa(tarefa.id)}>✕</button>
          </li>
        ))}
      </ul>

      {tarefas.length === 0 && <p>Nenhuma tarefa. Adicione uma!</p>}
    </div>
  );
}

export default App;

Conceitos-chave usados neste projeto:

  • spread operator (...tarefas): cria uma cópia do array e adiciona o novo elemento. NUNCA use push() diretamente no array de estado — o React não detectará a mudança.
  • filter: retorna novo array com apenas os elementos que satisfazem a condição. Não modifica o array original.
  • onKeyDown: evento disparado ao pressionar qualquer tecla. e.key === 'Enter' detecta a tecla Enter.
  • Date.now(): retorna o timestamp atual em milissegundos — útil como ID único temporário.

10. Hook useEffect

O useEffect permite executar efeitos colaterais em componentes funcionais. Efeitos colaterais são operações que acontecem "fora" do fluxo de renderização: chamadas de API, manipulação do DOM, timers, subscrições a eventos.

Sintaxe:

import { useEffect } from 'react';

useEffect(() => {
  // código do efeito
  return () => {
    // função de cleanup (limpeza) — opcional
  };
}, [dependencias]); // array de dependências

Os 3 comportamentos do array de dependências:

Array de dependênciasQuando o efeito executaEquivalente a (Classes)
[] (vazio)Uma única vez após a montagem do componentecomponentDidMount()
[a, b] (com variáveis)Após montagem E sempre que a ou b mudaremcomponentDidUpdate() com verificação
(sem array)Após TODA re-renderização (use com cuidado!)componentDidUpdate() sem verificação
import { useState, useEffect } from 'react';

function ExemploEffect() {
  const [dados, setDados] = useState(null);
  const [busca, setBusca] = useState('');

  // Executa apenas uma vez (montagem) — busca inicial
  useEffect(() => {
    console.log('Componente montado!');
    buscarDados();
  }, []);

  // Executa sempre que 'busca' mudar
  useEffect(() => {
    if (busca) {
      console.log(`Buscando por: ${busca}`);
      // chamar API de busca...
    }
  }, [busca]);

  async function buscarDados() {
    const resposta = await fetch('https://api.example.com/dados');
    const json = await resposta.json();
    setDados(json);
  }

  return <div>{dados ? JSON.stringify(dados) : 'Carregando...'}</div>;
}

12. Backend com Express.js

Express.js é um framework minimalista para Node.js que facilita a criação de servidores HTTP e APIs RESTful.

Instalação e configuração:

# Criar projeto backend
mkdir meu-backend
cd meu-backend
npm init -y
npm install express cors

Estrutura básica de um servidor Express:

// index.js — servidor Express
const express = require('express');
const cors = require('cors');

const app = express();
const PORT = 3001;

// Middlewares
app.use(cors({
  origin: 'http://localhost:5173'   // permite apenas o frontend em dev
}));
app.use(express.json());            // parseia body JSON automaticamente

// Rota GET simples
app.get('/api/alunos', (req, res) => {
  const alunos = [
    { id: 1, nome: 'Ana Silva', nota: 9.5 },
    { id: 2, nome: 'João Souza', nota: 7.0 }
  ];
  res.json(alunos);   // responde com JSON
});

// Rota GET com parâmetros de query
// URL: /api/numeros?quantidade=10&max=100
app.get('/api/numeros', (req, res) => {
  const quantidade = parseInt(req.query.quantidade) || 5;
  const max = parseInt(req.query.max) || 100;

  const numeros = Array.from(
    { length: quantidade },
    () => Math.floor(Math.random() * max) + 1
  );

  res.json({ numeros, quantidade, max });
});

// Rota POST — recebe dados no body
app.post('/api/alunos', (req, res) => {
  const { nome, nota } = req.body;
  if (!nome || nota === undefined) {
    return res.status(400).json({ erro: 'Nome e nota são obrigatórios' });
  }
  // ... salvar no banco
  res.status(201).json({ id: Date.now(), nome, nota });
});

// Rota com parâmetros de rota
app.get('/api/alunos/:id', (req, res) => {
  const id = parseInt(req.params.id);
  // ... buscar aluno pelo id
  res.json({ id, nome: 'Ana Silva', nota: 9.5 });
});

app.listen(PORT, () => {
  console.log(\`Servidor rodando em http://localhost:\${PORT}\`);
});

13. React consumindo API

O padrão de consumo de API em React envolve: 3 estados (dados/loading/erro), função assíncrona com fetch, try/catch/finally, e useEffect para disparar a busca.

import { useState, useEffect } from 'react';
import './App.css';

function App() {
  // Estado 1: dados retornados pela API
  const [numeros, setNumeros] = useState([]);
  // Estado 2: indicador de carregamento
  const [loading, setLoading] = useState(false);
  // Estado 3: mensagem de erro (null = sem erro)
  const [erro, setErro] = useState(null);

  // Função assíncrona para buscar dados
  async function buscarNumeros() {
    setLoading(true);   // mostra spinner/loading
    setErro(null);      // limpa erro anterior

    try {
      const resposta = await fetch('http://localhost:3001/api/numeros?quantidade=10&max=50');

      if (!resposta.ok) {
        throw new Error(`Erro HTTP: ${resposta.status}`);
      }

      const dados = await resposta.json();
      setNumeros(dados.numeros);

    } catch (err) {
      setErro(err.message || 'Falha ao conectar com o servidor.');
      setNumeros([]);   // limpa dados em caso de erro

    } finally {
      setLoading(false);  // sempre remove o loading, seja sucesso ou erro
    }
  }

  // Busca automática ao montar o componente
  useEffect(() => {
    buscarNumeros();
  }, []);  // [] = executa apenas uma vez

  return (
    <div className="app">
      <h1>Números Aleatórios</h1>

      <button onClick={buscarNumeros} disabled={loading}>
        {loading ? 'Buscando...' : 'Buscar Novos Números'}
      </button>

      {loading && <p className="loading">⏳ Carregando...</p>}

      {erro && (
        <div className="erro">
          <p>❌ Erro: {erro}</p>
          <button onClick={buscarNumeros}>Tentar novamente</button>
        </div>
      )}

      {!loading && !erro && numeros.length > 0 && (
        <ul>
          {numeros.map((num, index) => (
            <li key={index}>{num}</li>
          ))}
        </ul>
      )}
    </div>
  );
}

export default App;

Fluxo de execução detalhado:

  1. Componente monta: useEffect dispara buscarNumeros().
  2. loading = true: mostra indicador de carregamento, desabilita botão.
  3. fetch: faz requisição HTTP GET para o backend Express.
  4. await resposta.json(): aguarda a resposta e converte de JSON para objeto JavaScript.
  5. try sucesso: setNumeros(dados.numeros) — atualiza o estado, re-renderiza.
  6. catch erro: setErro(err.message) — exibe mensagem de erro.
  7. finally (sempre): setLoading(false) — remove o loading independente do resultado.

Por que 3 estados separados (e não um único objeto)?

Cada estado muda independentemente. Se colocássemos tudo em um objeto, qualquer atualização precisaria copiar todo o objeto. Separar permite atualizações mais simples e claras.

Padrão async/await com try/catch/finally:
try: código que pode falhar (requisição de rede).
catch(err): código executado se houver erro — recebe o objeto Error.
finally: código executado SEMPRE (sucesso ou erro) — ideal para limpar loading.

14. Resumo — O que cai na prova

HTML — Pontos essenciais:
  • form: action (destino), method (GET/POST).
  • fieldset + legend: agrupam campos visualmente.
  • label for="id": clique vai para o campo — acessibilidade.
  • Tipos de input: text, password, email, number, range, date, checkbox, radio, file, hidden.
  • Atributos: required, placeholder, min/max, minlength/maxlength, pattern, disabled, readonly, checked.
  • datalist: sugestões para input de texto (lista não restritiva).
  • select + option + optgroup: lista suspensa com agrupamento.
  • textarea: campo de texto multilinha (rows, cols).
  • table: thead, tbody, tfoot, tr, th, td. colspan (merge colunas), rowspan (merge linhas).
React — Pontos essenciais:
  • Componente funcional: função JS que retorna JSX. Nome começa com maiúscula.
  • JSX: className (não class), htmlFor (não for), tags sempre fechadas, uma raiz, {} para JS.
  • Props: parâmetros passados pelo pai. Somente leitura. Uso: function Comp(props) ou destructuring.
  • useState: const [valor, setValor] = useState(inicial). Re-renderiza ao atualizar.
  • Input controlado: value={estado} + onChange={(e)=>set(e.target.value)}.
  • Listas: .map() retorna JSX. key obrigatório. Não use índice como key quando possível.
  • Renderização condicional: ternário cond ? a : b ou short-circuit cond && a.
  • spread operator: [...arr, novoItem] para adicionar ao array de estado.
  • filter: arr.filter(t => t.id !== id) para remover do estado.
  • useEffect(fn, []): executa uma vez após montagem. [dep]: toda vez que dep muda.
  • async/await + try/catch/finally: chamar API. finally sempre limpa o loading.
  • Padrão API: 3 estados (dados, loading, erro) + buscarDados() + useEffect(()=>{buscarDados()},[]).
  • Express: app.use(cors()), app.use(express.json()), app.get/post(rota, handler). req.query, req.params, req.body, res.json().
